# 信号核心阶段推进说明 V0.4

依据外部冻结文档《STM32F407 四通道相干信号发生器——Level 2 方案冻结文档 V0.4》，本轮只推进能够在现有 AD9959 接线与 CubeMX 配置上安全实现的软件部分。

## 1. 阶段结论

| 冻结阶段 | 本轮状态 | 说明 |
|---|---|---|
| M1 AD9959 单通道 | 软件测试入口就绪 | 上电只启用 CH1，默认 1 MHz；提供 1 kHz、100 kHz、1 MHz、5 MHz、10 MHz、20 MHz 六个测试点 |
| M2 VCA810 单测 | 等待实物测试 | 不接 AD9959，不属于固件可替代的工作 |
| M3 AD9959 + VCA810 | 等待 M1/M2 实测通过 | 未加入虚构的增益或 Vpp 映射 |
| M4 四通道相干 | 软件控制就绪，等待示波器验收 | 支持四路同相、两路 I/Q、四相及四路自定义参数；一次 IO_UPDATE 生效 |
| M5 DAC8552 + VCA810 | 未开始 | VGAIN 方向、范围和增益曲线未实测，不冻结 DAC 码值 |
| M6 FreeRTOS + LVGL | 未开始 | 本轮不修改 HMI，不引入 RTOS |
| M7 Sweep / 调制 | 软件步进 Sweep 就绪 | 使用 HAL 毫秒时基的非阻塞步进扫频；不等同于硬件线性扫频、快速跳频、FSK 或 PSK |

## 2. M1 测试频点

固件内置频点：

```text
0: 1 kHz
1: 100 kHz
2: 1 MHz
3: 5 MHz
4: 10 MHz
5: 20 MHz
```

调用示例：

```c
/* 只打开 CH1，并切换到 5 MHz 测试点。 */
(void)App_SignalGenerator_ApplyM1TestPoint(3U);
```

`App_SignalGenerator_Init()` 默认选择索引 2 对应的 1 MHz 基线，CH2～CH4 的 ASF 设置为 0，避免上电越过冻结方案的 M1 验收顺序。

现有 USART1（115200、8N1）还提供了无需 HMI 的板级验收命令：

| 命令 | 动作 |
|---|---|
| `0`～`5` | 切换到对应 M1 测试点，只启用 CH1 |
| `c` | 当前频率下只启用 CH1 |
| `a` | 当前频率下四路同相 |
| `i` | 当前频率下启用 CH1/CH2 I/Q，静音 CH3/CH4 |
| `q` | 当前频率下启用 0°/90°/180°/270° 四相 |
| `s` | 1～10 MHz、1 MHz 步进、500 ms 驻留，单次扫频 |
| `r` | 同一参数循环扫频 |
| `x` | 停止继续扫频，保持当前输出 |
| `h` 或 `?` | 打印命令帮助 |

串口只在主循环中轮询单字节命令，不启用 USART 中断、DMA 或 RTOS。

## 3. M4 相干模式

四路同相：

```c
(void)App_SignalGenerator_SetPattern(
    APP_SIGNAL_PATTERN_IN_PHASE,
    1000000UL,
    1023U);
```

两路 I/Q：

```c
(void)App_SignalGenerator_SetPattern(
    APP_SIGNAL_PATTERN_IQ,
    1000000UL,
    1023U);
```

I/Q 模式使用 CH1=0°、CH2=90°，CH3、CH4 静音。四相模式使用：

```c
(void)App_SignalGenerator_SetPattern(
    APP_SIGNAL_PATTERN_FOUR_PHASE,
    1000000UL,
    1023U);
```

对应相位为 CH1=0°、CH2=90°、CH3=180°、CH4=270°。如需四路独立频率、幅度和相位，使用 `App_SignalGenerator_ApplyChannels()`。

## 4. M7 软件步进扫频

先设置需要保持的通道模式，再启动扫频。例如四相输出从 1 MHz 扫到 10 MHz：

```c
static const App_SignalSweepConfig sweep = {
    1000000UL,   /* start_frequency_hz */
    10000000UL,  /* stop_frequency_hz */
    100000UL,    /* step_frequency_hz */
    100U,        /* dwell_time_ms */
    0U           /* repeat */
};

(void)App_SignalGenerator_SetPattern(
    APP_SIGNAL_PATTERN_FOUR_PHASE,
    sweep.start_frequency_hz,
    1023U);
(void)App_SignalGenerator_StartSweep(&sweep);
```

主循环现有的 `App_SignalGenerator_Process()` 会依据 `HAL_GetTick()` 非阻塞推进频率。支持升频、降频、终点钳位和循环扫频；调用 `App_SignalGenerator_StopSweep()` 只停止继续步进，不关闭当前输出。

### 时序边界

- 扫频时间分辨率是 1 ms，实际步间隔还包含 GPIO 模拟串行写四通道寄存器的耗时。
- 每一步仍通过同一个最终 IO_UPDATE 同步更新四路。
- 该实现用于慢速功能验证和未来 UI/任务层接入，不宣称快速跳频性能。
- AD9959 Profile 引脚 P0～P3 尚未接入 MCU，不能把本实现描述为硬件 FSK/PSK。

## 5. 参数和硬件边界

- 应用层频率范围扩展为 1 Hz～30 MHz，对应冻结方案的低频扩展到挑战频段；底层 AD9959 驱动虽允许更高频率，但应用层会拒绝 30 MHz 以上请求，留给后续专项测试解锁。
- `amplitude` 是 0～1023 的 DDS ASF 原始码，不是 Vpp。
- VCA810、LPF、线缆和 50 Ω 负载引起的幅度及相位误差必须实测。
- 当前没有 AD9959 寄存器读回，软件成功状态只表示写时序已执行。

## 6. 上板验收顺序

1. 先用六个 M1 测试点逐个记录 CH1 的频率、高阻 Vpp、50 Ω Vpp 和波形。
2. 单独完成 VCA810 的 VGAIN→增益曲线，确认增益方向、削顶和自激边界。
3. 完成 AD9959 + VCA810 主链后，再测试 M4 的 I/Q 与四相输出。
4. 最后运行慢速 Sweep，确认每一步频率、终点和循环行为。
5. M1/M2/M3 未通过前，不接 DAC8552 自动幅度闭环，也不把 ASF 写成 Vpp。
