# STM32F407 四通道信号发生器

基于 STM32F407ZGTx、AD9959 和 LVGL 的信号发生器固件。当前分支已完成信号核心与 HMI 的基础集成，并通过现有硬件验证。

## 当前可用功能

- 上电默认启用 CH1，输出 1 MHz 正弦波。
- AD9959 支持单通道、四路同相、双路 I/Q、四相和四路自定义配置。
- USART1 使用 115200、8N1，可通过 `0`～`5` 切换六个单通道测试频点。
- LCD、触摸输入和 LVGL 页面正常运行，切换页面或持续刷新波形不会干扰 DDS 输出。
- UI 参数只在对应通道发生变化时写入 DDS，初始化时保留信号核心建立的上电基线。
- 支持基于 HAL 毫秒时基的非阻塞软件步进扫频。

## 串口测试命令

| 命令 | 动作 |
|---|---|
| `0` | CH1 输出 1 kHz |
| `1` | CH1 输出 100 kHz |
| `2` | CH1 输出 1 MHz |
| `3` | CH1 输出 5 MHz |
| `4` | CH1 输出 10 MHz |
| `5` | CH1 输出 20 MHz |
| `c` | 当前频率下只启用 CH1 |
| `a` | 当前频率下四路同相 |
| `i` | 当前频率下启用 CH1/CH2 I/Q |
| `q` | 当前频率下输出 0°/90°/180°/270° 四相 |
| `s` | 单次执行 1～10 MHz 软件步进扫频 |
| `r` | 循环执行软件步进扫频 |
| `x` | 停止扫频并保持当前输出 |
| `h`、`?` | 打印帮助 |

## 构建

工程使用 CMake、Ninja 和 GNU Arm Embedded Toolchain：

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

使用 STM32 for VS Code 时，也可以直接运行扩展提供的 Debug Build 任务。生成文件位于 `build/Debug/`。

## 已验证基线

当前硬件测试结果：

- CH1 上电 1 MHz 输出正常。
- 串口 `0`～`5` 六个频点切换正常。
- 恢复 LCD 初始化和 LVGL 刷新后，页面切换及持续波形刷新正常。
- 修复 UI 适配层后，由 UI 修改频率不会再出现固定比例偏差。

这里的 `amplitude` 仍是 AD9959 的 0～1023 ASF 原始码。UI 中的 Vpp 显示目前属于控制量映射，不代表经过负载测量和标定后的实际输出电压。

## 工程边界与下一阶段

- `signal_generator.ioc` 和 CubeMX 生成文件应通过 CubeMX 或既有 `USER CODE` 区域维护。
- AD9959 当前使用 GPIO 模拟串行时序；PB3、PB4、PB5 不应直接假定为空闲 SPI1 总线。
- 下一阶段先独立测量 VCA810 的 `VGAIN → 增益/Vpp` 曲线、控制方向、削顶和自激边界。
- VCA810 单测通过后，再连接 AD9959；最后加入 DAC8552，并根据实测数据建立目标 Vpp 到 DAC 码的标定关系。

更完整的信号核心接口、扫频说明和上板验收顺序见 [docs/信号核心阶段推进_V0.4.md](docs/信号核心阶段推进_V0.4.md)。
